
: = v-bind 축약
v-bind:key	:key	요소 고유 식별
v-bind:name	:name	속성 바인딩
v-bind:style	:style	스타일 동적 적용
v-on:click	@click	이벤트 핸들링

:key는 Vue의 특수 속성으로, 리스트 렌더링이나 컴포넌트 재생성을 제어합니다.
:key = Vue가 요소/컴포넌트를 식별하는 고유 키
키가 바뀌면 Vue는 해당 요소/컴포넌트를 완전히 제거하고 새로 생성합니다 (리셋)
attribute는 아니고, **Vue의 지시어(directive)**입니다

- 사용 예시
1. 리스트 렌더링에서 key (필수)
<div v-for="item in items" :key="item.id">
  {{ item.name }}
</div>

각 item을 고유하게 식별 (순서 변경 시 상태 유지)

2. 컴포넌트 리셋
<!-- 조건이 바뀔 때마다 컴포넌트 새로 생성 -->
<MyComponent :key="userId" />

3. 라우트 기반
<Header :key="$route.fullPath" />
<!-- 경로 변경 → Header 완전 리셋 -->

- key 없을 때 vs 있을 때

<!-- key 없음: Header 상태 유지 (input 값 등) -->
<Header :isDarkMode="isDarkMode" />

<!-- key 있음: 라우트 변경할 때마다 Header 초기화 -->
<Header :key="$route.fullPath" :isDarkMode="isDarkMode" />

- 데이터 바인딩

interpolation (보간)	  ->  {{ data }}	텍스트/값 표시만	단방향 (부모 → 자식)
v-bind	:속성="data"	  ->  속성/props 바인딩	단방향 (부모 → 자식)
v-model	v-model="data"  ->	양방향 동기화	양방향 (부모 ↔ 자식)

- 3가지 데이터 바인딩 예시
<!-- 1. {{ }} 보간 — 텍스트 표시만 (읽기) -->
<p>{{ message }}</p>  <!-- "Hello" 출력 -->

<!-- 2. v-bind (:) — 속성/props 바인딩 (부모 → 자식) -->
<img :src="imagePath" :alt="imageAlt" />
<Header :isDarkMode="isDarkMode" />

<!-- 3. v-model — 양방향 (입력 폼에서 자주 사용) -->
<input v-model="searchText" />  <!-- 입력값이 자동으로 searchText 업데이트 -->
<input v-model.number="count" />  <!-- 숫자로 변환 -->

v-model 상세
// v-model = :value + @input 의 축약
<input v-model="message" />

<!-- 위와 동일 -->
<input :value="message" @input="message = $event.target.value" />


-------------------------------------------------------------------------------------------

- attribute: HTML 표준 속성 (class, id, data-*, style 등)
Vue의 boolean attribute 특성
:disabled, :checked, :readonly 등 boolean attribute는
true면 attribute 자체가 HTML에 나타나고,
false면 attribute가 아예 없어집니다.

- props: Vue 컴포넌트에 전달하는 데이터 (자식 컴포넌트에서 defineProps로 선언해야 받을 수 있음)
v-bind (:): props를 자식 컴포넌트에 전달하는 문법

:disabled="조건" = attribute binding (HTML 속성을 동적으로 제어)
:prop="값" = props binding (컴포넌트에 데이터 전달)

<script setup>에서는 최상위(top-level)에 선언된 모든 것(변수, 함수, import)이 
자동으로 템플릿에 노출됩니다.

const props = defineProps({
  currentPage: { type: Number, required: true },
  totalPages: { type: Number, required: true },
  isMob: { type: Boolean, default: false }
})

props 변수에 저장했어도
템플릿에서 {{ currentPage }}, {{ totalPages }}, {{ isMob }}로 직접 접근 가능합니다.
Vue가 내부적으로 props 객체의 속성들을 자동으로 템플릿 스코프에 추가하기 때문입니다.

<!-- 템플릿에서 직접 접근 (props 변수 호출 안 함) -->
{{ currentPage }}  <!-- props.currentPage와 동일하게 동작 -->
{{ totalPages }}   <!-- props.totalPages와 동일하게 동작 -->
{{ isMob }}        <!-- props.isMob과 동일하게 동작 -->

중요한 점: defineProps()에서 바로 구조분해하면 반응성(reactivity)을 잃습니다 
— 즉 스냅샷(초기값)만 가져오므로 이후 변경이 템플릿에 반영되지 않음.

// 위험: 반응성 잃음 (스냅샷)
const props = defineProps({ currentPage: Number });
// const { currentPage } = props; // 이렇게 구조분해 하면 reactive가 사라짐

// 유지 방법 1: toRefs 사용 (추천)
import { toRefs } from 'vue';
const props = defineProps({ currentPage: Number });
const { currentPage } = toRefs(props); // currentPage는 ref가 됨, 템플릿에서 바로 사용 가능

// 유지 방법 2: computed 사용
import { computed } from 'vue';
const props = defineProps({ currentPage: Number });
const currentPage = computed(() => props.currentPage);

$event는 Vue에서 이벤트 핸들러에 자동으로 전달되는 이벤트 객체입니다.

- 예시
<a v-if="project.url" :href="project.url" target="_blank" rel="noopener noreferrer" class="copy-to-clip" @click="copyProjectUrl($event, project.url)">라이브</a>

const copyProjectUrl = (e: Event, url: string) => {
  e.preventDefault()  // <-- $event 사용 (기본 동작 방지)
  common.copyToClipboard(url)
  common.toastPopup('프로젝트 URL이 복사되었습니다.')
}

@click="copyProjectUrl($event, project.url)"
$event = 클릭 이벤트 객체 (MouseEvent)
project.url = 프로젝트 URL

<!-- 아래 두 가지는 동일 -->
@click="copyProjectUrl($event, project.url)"
@click.prevent="copyProjectUrl(project.url)"  <!-- .prevent는 preventDefault() 자동 실행 -->

[요약]
$event = 이벤트 객체 자체
함수에서 e.preventDefault() 같이 이벤트 제어가 필요하면 $event 전달
.prevent modifier로 간단히 할 수도 있음

$route는 Vue Router에서 제공하는 현재 라우트 정보 객체입니다.

$route = 현재 활성화된 라우트의 정보 (읽기 전용)
$router = 라우트를 제어하는 객체 (네비게이션 등)

- 예시
<Header :key="$route.fullPath" :isDarkMode="isDarkMode" @update:themeStatus="toggleTheme"/>

:key="$route.fullPath"
라우트 경로가 바뀔 때마다 Header 컴포넌트를 새로 생성(리셋)
fullPath = 전체 경로 (예: /portfolio?page=2)

- 자주 쓰는 $route 속성들

속성	설명	예시
$route.path	현재 경로	/portfolio
$route.fullPath	쿼리 포함 전체 경로	/portfolio?page=2
$route.name	라우트 이름	'portfolio'
$route.params	URL 파라미터	{ id: '123' }
$route.query	쿼리 파라미터	{ page: '2' }

- 사용예시

// 경로 이동 감지
import { watch } from 'vue';
import { useRoute } from 'vue-router';

const route = useRoute();

watch(() => route.fullPath, (newPath) => {
  console.log('경로 변경:', newPath);
  // 예: scrollAnimation 재초기화
})

템플릿에서는 Vue가 자동으로 ref/computed를 언래핑(unref)해서 보여줍니다.
그래서 템플릿 안에서는 ref.value를 쓰지 않아도 됩니다.

스크립트(자바스크립트/타입스크립트) 영역에서는 ref나 computed로 만든 값에 접근할 때 반드시 .value를 써야 합니다.
computed가 배열을 반환해도 내부적으로는 ref이기 때문에 동일하게 동작합니다
(템플릿 → 자동 언래핑, 스크립트 → .value).

언래핑(unwrapping) = Vue가 템플릿에서 ref/computed의 .value를 자동으로 꺼내 보여주는 동작.
=> 템플릿에서는 ref나 computed를 그대로 쓰면 됨(예: {{ count }}), 스크립트에서는 .value 필요(예: count.value).
ref = 반응성 단일 값 래퍼. 내부 값은 .value로 읽고 쓴다.
computed = 의존 값에 따라 자동으로 재계산되는 "캐시된" ref. getter(읽기전용) 또는 getter/setter(쓰기 가능)로 만들 수 있음.
=> 스크립트에서는 computedResult.value, 템플릿에서는 그냥 computedResult.
reactive = 객체 전체에 반응성 부여. 객체 내부 프로퍼티를 직접 접근(reactiveObj.foo).
구조분해(destruction)는 반응성 잃을 수 있으니 toRefs/toRef로 변환해 사용.
